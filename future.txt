🔹 UPDATED PROMPT 3 — KEY INFORMATION EXTRACTION + AI SEARCH (AI FEATURE 3)

Applies to: PDF, TXT, DOCX, receipts, invoices, certificates
Model: dslim/bert-base-NER

📌 Prompt
Implement AI Key Information Extraction (NER) with AI-powered search for StoreEase.

FEATURE DETAILS:
- Applies to document files:
  PDF, TXT, DOCX, receipts, invoices, certificates
- Uses Hugging Face model: dslim/bert-base-NER
- Extract key entities such as:
  Names, Dates, Amounts, Organizations, Locations

BACKEND FLOW (must follow exactly):
Cloudinary file URL
→ Download file
→ Extract plain text
→ Send text to NER model
→ Parse and group entities
→ Store structured result in Prisma File.aiMetadata.entities

API REQUIREMENTS (NER):
- Create POST API route /api/ai/entities
- Authenticate user via JWT cookie
- Accept fileId
- Fetch file and verify ownership
- Skip extraction if aiMetadata.entities already exists
- Store entities in the following format:

{
  "entities": {
    "name": ["Harshita Gawas"],
    "date": ["12 June 2025"],
    "amount": ["15000"],
    "organization": ["XYZ University"]
  }
}

UI REQUIREMENTS (NER DISPLAY):
- Use the SAME right-side AI preview drawer
- Heading:
  "🧠 Key Information"
- Display entities in a clean label-value layout
- Show section only if entities exist
- Human-readable values only
- No raw tokens, no confidence scores

--------------------------------------------------
AI-POWERED SEARCH (VERY IMPORTANT)
--------------------------------------------------

SEARCH FEATURE DETAILS:
- Add a search bar at the top of the Files page
- Search input should match against:
  - File name
  - aiMetadata.entities values (names, dates, amounts, organizations, locations)

BACKEND SEARCH LOGIC:
- Create a GET API route /api/files/search
- Authenticate user
- Accept query string (?q=)
- Search user's files where:
  - filename contains query OR
  - aiMetadata.entities contains query
- Return matched files only (no AI generation here)

FRONTEND SEARCH BEHAVIOR:
- Search should work even if filename does NOT match
- Typing "Harshita", "15000", or "Invoice" should list relevant files
- Debounce input for performance
- Show results in existing Files list/grid
- If search is empty, show normal file list

DESIGN RULES:
- Clean search bar (no filters UI for now)
- Instant feedback
- No page reload
- Desktop-first, mobile-safe


✅ Outcome:
Documents become structured, searchable, and feel genuinely “smart”.
